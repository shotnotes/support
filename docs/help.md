# Getting help

You need a GitHub account to open an issue or start a discussion. Everything
there is public.

- **Something doesn't work:** [report a problem](https://github.com/shotnotes/support/issues/new?template=bug_report.yml).
  The app's "Report a problem" fills in the version, the system and the device
  for you. For the computer programs, say the version with its build number, such
  as `0.1.0 (8)`: `shotnotes version` prints it, and the desktop app shows it at
  the foot of its settings.
- **An idea or a change you would like:** [suggest a feature](https://github.com/shotnotes/support/issues/new?template=feature_request.yml),
  or talk it over first in [Ideas](https://github.com/shotnotes/support/discussions/categories/ideas).
- **A typo or unclear text**, on the website, in the app, in the install
  instructions or in a store listing: [report it](https://github.com/shotnotes/support/issues/new?template=text_problem.yml).
- **A question:** search these pages first, then ask
  in [Q&A](https://github.com/shotnotes/support/discussions/categories/q-a).
- **A security problem:** don't open an issue. Read the
  [security policy](https://github.com/shotnotes/support/security/policy), which
  explains how to report it privately.

!!! warning "Everything is public"

    Shots can hold coordinates and the names of places. Before you paste a log
    or attach an export file or a screenshot, remove anything you would rather
    not make public.

## What happens to a report

Each report is read and labelled with the part it is about. When it needs more
detail, it gets **needs info** and a question. When it is taken on, it gets
**tracked**, and stays open until a release fixes it or brings the feature.
Reports that can't be acted on are closed with a reason.
